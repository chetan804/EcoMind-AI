# Development and deployment runbook

## Prerequisites
Git, Python 3.11 or 3.12, Node.js 22.22+ and npm, GNU Make. Docker with Compose v2 for the containerized stack and `make db-up`. (Without Docker, any PostgreSQL 14+ works for host-based development.)

## A. Fastest path: everything in containers
```bash
git clone https://github.com/chetan804/EcoMind-AI.git && cd EcoMind-AI
make env      # creates .env, backend/.env, frontend/.env from templates; generates secrets; never overwrites
make up       # builds images; starts db -> migrations -> backend -> frontend; waits until healthy
python3 tests/smoke/smoke.py --api http://localhost:8000 --web http://localhost:5173
```
Open http://localhost:5173/settings/system-status (System status page) and http://localhost:8000/api/v1/docs. Stop with `make down` (keeps data). Logs: `make logs`.

**Startup sequence (enforced by `compose.yaml`):** `db` healthy (`pg_isready`) → `migrate` runs `alembic upgrade head` and exits 0 → `backend` starts and becomes healthy when `/ready` answers 200 → `frontend` starts.

## B. Host-based development (hot reload, debugger)
```bash
make setup                     # env files + backend/.venv (backend, ml, dev tools) + frontend node_modules
make db-up                     # PostgreSQL only, in Docker (or use your own and edit backend/.env)
make migrate                   # alembic upgrade head using backend/.env
make backend-dev               # terminal 1: http://localhost:8000
make frontend-dev              # terminal 2: http://localhost:5173 (proxies /api, /health, /ready to :8000)
```
`backend/.env` `DATABASE_URL` must point at `localhost:${POSTGRES_PORT}` with the password from the root `.env` (`make env` keeps them equal).

## Environment files
| File | Used by | Template |
|---|---|---|
| `.env` | Docker Compose | `.env.example` |
| `backend/.env` | backend on the host, Alembic, pytest settings | `backend/.env.example` |
| `frontend/.env` | Vite on the host | `frontend/.env.example` |
Variables are documented in each template. Missing/invalid backend settings stop the app at startup with a validation error naming the variable.

## Database migrations
```bash
make migrate                           # apply
make migration m="add widgets table"   # autogenerate (needs a database at the current head)
```
Rules: review every autogenerated migration by hand; never edit a migration that has been merged/applied; one logical change per migration; add a failing-insert test for each new constraint; run `make data-dictionary`; ensure `alembic check` reports no drift (the integration tests do). Never use `create_all()`. **Never reset or drop a database to make a migration pass**: write a corrective migration. Destructive operations on shared data need a backup and a rollback plan first.

Safe migration test (throw-away database, never your dev data): `make test-backend` creates an isolated `ecomind_test_*` database, runs `upgrade head`, checks drift, runs `downgrade base` and `upgrade head` again, then drops it. Provide the server with `TEST_DATABASE_URL` (the Makefile derives it from `.env` for the Compose database; the role must be able to create databases, which the Compose `POSTGRES_USER` can).

## Quality commands
```bash
make lint typecheck        # ruff, mypy, ESLint, tsc
make test                  # backend (incl. DB), frontend, ml, contract
make check                 # structure + env-template checks
make install-e2e && make test-e2e   # needs the stack running (make up)
make compose-config        # validate compose.yaml
```

## Deploying (outline; no production environment exists yet)
1. Build images: `docker build -f deployment/docker/backend.Dockerfile -t ecomind-backend .` and `docker build -f deployment/docker/frontend.Dockerfile --target production --build-arg VITE_API_BASE_URL=https://<api-origin> -t ecomind-frontend .`
2. Provision PostgreSQL (backups on), persistent file storage, secret store.
3. Set backend environment (see `backend/.env.example`) with `ENVIRONMENT=production`, strong `SECRET_KEY`, `REFRESH_COOKIE_SECURE=true`, explicit `CORS_ALLOWED_ORIGINS` (the frontend origin).
4. Run `alembic upgrade head` once as a release step (`docker run --env-file … ecomind-backend alembic upgrade head`).
5. Start backend (`/health` liveness, `/ready` readiness probes), then the frontend.
6. Verify: `python tests/smoke/smoke.py --api https://<api> --web https://<web>`.
Rollback: see [`backup-and-rollback.md`](backup-and-rollback.md). Redeploying the previous image is only safe when the migrations since that image were additive (new tables or nullable columns, as 0009 and 0010 are); this is **not guaranteed** in general, so check each migration. `alembic downgrade` drops the data of the migrations it reverses, so take a backup first.

## Maps and vehicle tracking
Full guide: [`../maps/GOOGLE_MAPS_INTEGRATION.md`](../maps/GOOGLE_MAPS_INTEGRATION.md). The product runs without any Google key (maps become labelled lists, route plans show straight lines).

| Variable | File | Purpose |
|---|---|---|
| `VITE_GOOGLE_MAPS_API_KEY`, `VITE_GOOGLE_MAPS_MAP_ID` | `frontend/.env`, root `.env` (dev container), **build args** of the production frontend image | browser key (referrer + Maps JavaScript API restricted) and map ID; compiled in at build time |
| `GOOGLE_MAPS_SERVER_API_KEY` | `backend/.env`, root `.env` | server key for the Routes API (IP restricted); never a `VITE_` variable |
| `GOOGLE_ROUTES_TIMEOUT_SECONDS` | backend | provider timeout (8) |
| `TRACKING_LIVE_WITHIN_SECONDS`, `TRACKING_STALE_AFTER_SECONDS` | backend | LIVE up to 120 s, DELAYED up to 900 s, then STALE |
| `TRACKING_MAX_FUTURE_SKEW_SECONDS`, `TRACKING_MAX_REPORT_AGE_HOURS`, `TRACKING_MAX_EVENTS_PER_MINUTE` | backend | ingestion validation and per-vehicle rate limit (120 s, 6 h, 30) |
| `TRACKING_RETENTION_DAYS` | backend | history kept (90) |
| `TRACKING_SIMULATOR_ENABLED` | backend | simulator on/off; unset means on outside production, off in production |

Production frontend image with maps: `docker build -f deployment/docker/frontend.Dockerfile --target production --build-arg VITE_API_BASE_URL=https://<api-origin> --build-arg VITE_GOOGLE_MAPS_API_KEY=<browser key> --build-arg VITE_GOOGLE_MAPS_MAP_ID=<map id> -t ecomind-frontend .` (the browser key is public by design; restrict it by referrer in Google Cloud).

**Daily job (the platform has no scheduler):** `python -m app.cli purge-location-events` removes position events older than `TRACKING_RETENTION_DAYS`, e.g. `0 3 * * * cd /app && python -m app.cli purge-location-events`. It writes an audit record.

Verify after enabling keys: open the Fleet screen (map instead of the "Google Maps is not configured" notice), open a route plan (road route, or the reason it is unavailable), and check the browser console for CSP violations. Watch the Google Cloud console for usage and set budget alerts.
